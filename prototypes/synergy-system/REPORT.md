## Prototype Report: 羁绊系统 (Synergy System)

### Hypothesis

羁绊检测和效果应用可以正确工作。特殊羁绊机制（狍子万能羁绊、EOE姐妹组合羁绊、hirro单挂效果）可以正确触发并提供预期的数值效果。

### Approach

**构建内容**:
- 简化的角色数据类（9个代表性角色）
- 简化的羁绊数据类（7个羁绊定义）
- 六边形棋盘系统（简化实现）
- 羁绊检测系统
- 羁绊效果系统
- Python测试脚本（无需Godot运行时）

**测试用例**:
1. VR羁绊 (2/4 阈值) - 验证普通羁绊阈值检测
2. EOE姐妹 (组合羁绊) - 验证特定角色组合触发
3. 狍子 (万能羁绊) - 验证可计入任意羁绊的机制
4. 单挂效果 (位置效果) - 验证基于位置的效果触发
5. 多羁绊叠加 - 验证一个角色拥有多个羁绊标签时的效果叠加

**耗时**: 约1小时

**简化内容**:
- 无UI渲染
- 无动画效果
- 使用Python替代GDScript（便于在无Godot环境测试）

### Metrics

- **测试通过率**: 18/18 (100%)
- **代码行数**: ~400行 Python
- **核心逻辑复杂度**: 中等
- **迭代次数**: 1次（首次实现即通过所有测试）

### Key Findings

1. **羁绊检测算法可行**: 基于角色标签统计+阈值判断的模式工作正常
2. **万能羁绊实现简单**: 狍子的"可计入任意羁绊"机制通过简单的计数补足实现
3. **组合羁绊逻辑清晰**: EOE姐妹通过检查特定角色ID是否都在场来判断
4. **位置效果可行**: 六边形邻居检测算法正确，单挂效果可实时计算

### Recommendation: **PROCEED**

羁绊系统的核心逻辑验证通过，可以进入生产实现阶段。

### If Proceeding

**架构要求**:
- 羁绊数据使用 Godot Resource (.tres) 存储
- 检测系统作为独立单例，响应棋盘变化事件
- 效果系统与属性计算系统集成
- 支持运行时热重载配置

**性能目标**:
- 羁绊检测 < 1ms（32格棋盘）
- 效果应用 < 0.5ms/角色
- 支持100+羁绊定义不降性能

**范围调整**:
- MVP阶段实现已测试的7个羁绊
- 隐藏羁绊（大厂）暂不实现
- 羁绊激活对话/特效延后到MVP+

**预估生产工作量**:
- 数据定义: 0.5天
- 检测系统: 1天
- 效果系统: 1天
- UI集成: 0.5天
- 测试覆盖: 0.5天
- **总计: 3-4天**

### Lessons Learned

1. **组合羁绊需要明确角色列表**: EOE姐妹的实现需要硬编码角色ID，后续可通过配置表定义
2. **单挂效果需要实时检测**: 当棋盘状态变化时需要重新检测孤立状态
3. **狍子的优先级需要UI支持**: 当多个羁绊都差1个时，狍子计入哪个需要玩家指定或自动选择
4. **效果叠加规则需要文档化**: 当前使用乘法叠加，需要在GDD中明确说明
